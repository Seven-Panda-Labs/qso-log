# Internationalization

The interface is translated. **Everything else is English**: code, comments, commits, issues, PRs, and documentation. This split is deliberate, contributors come from everywhere and a single working language keeps the repo readable.

## Shipped locales

| Code | Language | File |
|------|----------|------|
| `en` | English (source) | [`src/i18n/locales/en.json`](../src/i18n/locales/en.json) |
| `es` | Español | [`src/i18n/locales/es.json`](../src/i18n/locales/es.json) |
| `fr` | Français | [`src/i18n/locales/fr.json`](../src/i18n/locales/fr.json) |
| `pt-PT` | Português | [`src/i18n/locales/pt-PT.json`](../src/i18n/locales/pt-PT.json) |

English is the source and the fallback: a missing translation shows English, never a raw key.

## How a language is chosen

1. The operator's saved choice, in `localStorage` under `qso-log.locale`
2. The browser language
3. English

Regional variants resolve to the closest locale shipped: `fr-CA` gets French, `es-MX` Spanish, `pt-BR` and `pt` get `pt-PT`, which is closer than English. `supportedLngs` does this on its own.

**Do not add `nonExplicitSupportedLngs`.** It collapses `pt-PT` to `pt`, which has no bundle, so every Portuguese browser silently falls back to English. There is a test for this in [`src/i18n/detection.test.ts`](../src/i18n/detection.test.ts).

## Terminology

Ham radio vocabulary is international by convention and **stays untranslated**, in every locale:

- Q codes: QSO, QTH, QRZ, QSL
- Signal reports: RST, and the `59` style values
- Band and mode names: `20m`, `SSB`, `CW`, `FT8`
- Callsigns and Maidenhead locators

Translating these does not help an operator, it makes the app unfamiliar. Translate the sentence around the term, not the term. A test asserts QSO survives in every locale.

Everything else is translated, including the words operators might expect in English. The logbook itself has a name in most languages: *carnet de trafic*, *libro de guardia*, *diário de estação*.

## Rules for strings

- **No string concatenation.** Word order differs between languages; use interpolation with named placeholders.
- **Dates, times, and numbers** go through locale formatting, never hand built. Remember UTC is the storage format, and the display may not be local time.
- **Keys describe meaning, not text.** `logbook.empty.title`, not `logbook.noContactsYet`.

## Adding a locale

1. Copy `src/i18n/locales/en.json` to `<code>.json` and translate the values, not the keys.
2. Add it to `languages` in [`src/i18n/languages.ts`](../src/i18n/languages.ts), with the language's own name for the label: `Français`, not `French`.
3. Run `npm run test`. The locale tests enforce the invariants: identical key sets, no empty strings, QSO untranslated.

That is the whole procedure. Translations are welcome contributions and need no radio background, only care with the terminology above.
