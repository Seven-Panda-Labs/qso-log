# Internationalization

> **Draft.** The mechanism lands with the scaffold; the rules below are settled.

The interface is translated. **Everything else is English**: code, comments, commits, issues, PRs, and documentation. This split is deliberate, contributors come from everywhere and a single working language keeps the repo readable.

## Terminology

Ham radio vocabulary is international by convention and mostly **stays untranslated**, in every locale:

- Q codes: QSO, QTH, QRZ, QSL
- Signal reports: RST, and the `59` style values
- Band and mode names: `20m`, `SSB`, `CW`, `FT8`
- Callsigns and Maidenhead locators

Translating these does not help an operator, it makes the app unfamiliar. Translate the surrounding sentence, not the term.

## Rules for strings

- **No string concatenation.** Word order differs between languages; use interpolation with named placeholders.
- **Dates, times, and numbers** go through locale formatting, never hand built. Remember UTC is the storage format and the display may not be local time.
- **Keys describe meaning, not text.** `log.entry.saved`, not `log.entry.savedSuccessfully`.
- **English is the source locale.** A missing translation falls back to English rather than showing a key.

## Adding a locale

*Open.* Documented once the i18n setup is committed. Translations are welcome contributions and need no radio background, only care with the terminology above.
